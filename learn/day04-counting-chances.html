Counting Becomes Probability

2. Exactly k Heads: Choosing Which Flips Are Heads

A sequence of flips with exactly k heads is decided by which positions get the H. The H's are identical (swap two and the sequence is unchanged), so that's C(n, k). Every sequence is equally likely, out of 2ⁿ in total. Click a bar.

Favourable: C(n, k)
Total: 2ⁿ
P(exactly k heads)

The same count works for anything with two identical outcomes: right/wrong answers when guessing, working/broken bulbs, A/B codes. It only becomes C(n, k) / 2ⁿ when both outcomes are 50/50. With a biased coin each sequence needs a weight, which is the binomial distribution on Day 5.

Rule 1: The Opposite Door

3. "At Least One" = 1 − "None"

"At least one success" covers 1, 2, 3, … successes, which is a lot of cases. Its opposite is a single case: zero successes, where every try fails. Multiply the per-try fail chances, then subtract from 1. The tempting shortcut, adding the chances (5% × 20 tries = 100%), is wrong: it counts overlapping successes twice and can go past 100%.

A jailbreak prompt that works with probability p, retried n times

One try fails: 1 − p
All n fail: (1 − p)ⁿ
At least one works
Wrong: n × p

The same rule with "at least two share"

What's the chance that at least two people share a weekday of birth? The opposite is: everyone is on a different day. Seat people one by one in empty days: the first has 7 free days out of 7, the second 6 of 7, and so on. The opposite of "at least k" is always "fewer than k", so think it through each time.

Rules 2 and 3: "Or"

4. Adding Without Counting Anyone Twice

A class of 20: some play football, some cricket, some both. Adding the two groups counts the "both" students twice, once in each circle. See the darker overlap? Remove it once. If the two things can't happen together (a sweet that is red or green), there's no overlap and you can simply add.

Football + cricket
At least one sport
Neither

Formula: P(A or B) = P(A) + P(B) − P(A and B) and if A, B can't happen together: P(A or B) = P(A) + P(B)
Same with percentages: 40% own a car, 30% a bike, 15% both. Car or bike = 40 + 30 − 15 = 55%, neither = 45%. Check: 25 car only + 15 both + 15 bike only + 45 neither = 100.
"Given That…"

5. Conditional Probability: Shrink the Room

"Given that the student plays football" throws everyone else out of the room. The given part sets the bottom of the fraction; the part you're asking about sets the top. Same class, same 5 students who play both, three different answers.

Students in the room
Of them, the ones we want
Probability

Formula: P(A given B) = P(A and B) / P(B) so in general P(A given B) ≠ P(B given A)
With percentages: 40% own a car, 15% own a car and a bike. P(bike given car) = 0.15 / 0.40 = 0.375. Dividing by 20 (or 100) everywhere changes nothing, which is why counts and percentages give the same answer. For an LLM judge, P(flagged given sycophantic) and P(sycophantic given flagged) are different numbers, and mixing them up is a classic overclaim.

The chain rule: one step at a time

Flip the formula and you get P(A and B) = P(A) × P(B given A): the second step happens in the room the first one left behind. A bag has 3 blue and 2 grey balls. What's the chance both draws are blue?

Two Words People Mix Up

6. Independent vs Mutually Exclusive

Independent

Knowing one doesn't change the other

Same chance in the small room as in the big room. Then P(A and B) = P(A) × P(B). Drawing with replacement, two coin flips, a card's suit and its rank (P(king) = 1/13, and P(king given heart) = 1/13 too).

Dependent

Knowing one changes the other

Drawing without replacement, rain and umbrellas, height and basketball. Linked doesn't mean caused, the same lesson as correlation on Day 3.

Mutually exclusive

They can't both happen

One die showing 1 and 6, one grade being A and C. P(A and B) = 0. The trap: these are strongly dependent, since getting a 1 drops the chance of a 6 from 1/6 to 0.

When the Maths Gets Hard

7. Monte Carlo: Simulate, Count, and Report the Error

Instead of working out the formula, play the game many times and count. Here: roll a die n times, and did at least one 6 appear? The estimate wobbles at first and settles near the exact answer 1 − (5/6)ⁿ. The standard error tells you how much to trust it, and it only shrinks with √N: four times the trials for half the error.

Games played N
Estimate p̂
SE = √(p̂(1 − p̂) / N)
Exact 1 − (5/6)ⁿ

For evaluations: "the model refused 40 of 100 prompts" is p̂ = 0.40 with SE ≈ 0.049, so roughly 30% to 50%. A 3-point difference between two models on 100 prompts is well inside that noise.

def factorial(n):
    if n < 0:
        raise ValueError("The number must be greater than or equal to zero")
    fact = 1
    count = n
    while count > 1:
        fact = fact * count
        count = count - 1
    return fact

def permutations(n, k):
    if n < 0 or k < 0 or k > n:
        raise ValueError
    count = n
    res = 1
    while count > n-k:
        res = res * count
        count = count - 1
    return res

def combinations(n, k):
    return permutations(n,k)//factorial(k)

def p_exactly_k_heads(n, k):
    return combinations(n,k)/2**n

def p_at_least_one(p, n):
    if p < 0 or p > 1 or n < 0:
        raise ValueError
    return 1 - (1-p)**n

def simulate_at_least_one_six(n_rolls, n_trials, rng):

    count = 0
    for _ in range(n_trials):
        rolls = rng.integers(1, 7, size=n_rolls)
        if 6 in rolls:

    return count/n_trials

function factorial(n) {
  if (n < 0) throw new Error("n must be >= 0");
  let fact = 1;
  for (let c = n; c > 1; c--) fact *= c;
  return fact;
}

function permutations(n, k) {
  if (n < 0 || k < 0 || k > n) throw new Error("need 0 <= k <= n");
  let res = 1;
  for (let c = n; c > n - k; c--) res *= c;   // k numbers going down
  return res;
}

function combinations(n, k) {
  return permutations(n, k) / factorial(k);   // remove the k! orderings
}

function pExactlyKHeads(n, k) {
  return combinations(n, k) / 2 ** n;
}

function pAtLeastOne(p, n) {
  if (p < 0 || p > 1 || n < 0) throw new Error("bad input");
  return 1 - (1 - p) ** n;                    // 1 − P(none)
}

function simulateAtLeastOneSix(nRolls, nTrials) {
  if (nTrials <= 0) throw new Error("nTrials must be positive");
  let count = 0;
  for (let t = 0; t < nTrials; t++) {
    for (let r = 0; r < nRolls; r++) {
      if (1 + Math.floor(Math.random() * 6) === 6) { count++; break; }
    }
  }
  return count / nTrials;
}
