Three ways to say “typical”

Mean: add everything up and divide by how many there are. Think of a seesaw: the mean is the point where the line balances. Every value pulls on it, so one very heavy weight far away drags the balance point toward it.

Median: sort the values and take the one in the middle. With an even count, average the two middle ones. It's the person in the middle of a queue: how far away the last person stands doesn't move them.

Mode: the value that appears most often. It's the only one of the three that still works when the values are words instead of numbers.

In the line-up above, heights are spread fairly evenly around the middle, so the mean and median almost agree. Add the basketball player and watch: the mean jumps more than the median, because the mean feels every centimetre of that one person.

Why is the mode “rarely useful” for heights? Measure precisely enough and nobody is exactly 172.000 cm, so every value appears once. For continuous data the mode becomes the peak of the distribution's curve, an idea that comes back with density functions on Day 5.

This is why news reports and governments quote the median household income. Whenever a few extreme values can appear on one side (salaries, house prices, website load times), the median is the safer summary. The mean is not wrong; it answers a different question: if all the money were shared out equally, how much would each person get?

When only the mode makes sense

Ask a class which programming language they like best. You can't add up “Python” and “Rust” and divide by two, and there's no natural order to find a middle in. The only question left is: which answer came up most often? Click to add votes.

Choosing one

Are the values categories?

Use the mode. Favourite language, city, colour.

Numbers, but skewed or with outliers?

Use the median. Rent in Bielefeld, salaries, response times.

Numbers, roughly symmetric?

Use the mean, because it uses every value. Heights of 1,000 adults, exam scores in a big class.

A useful habit: compute both the mean and the median. If they're close, the data is roughly symmetric. If the mean is much higher than the median, a few large values are pulling it up.

The code behind it

I wrote these three functions from scratch in Python on Day 1 of my ml-from-scratch repo. The interactive figures on this page run the same logic, ported to JavaScript.

# Python (my original)
def mean(xs: list[float]) -> float:
    if len(xs) == 0:
        raise ValueError("mean() requires at least one value")
    return sum(xs) / len(xs)


def median(xs: list[float]) -> float:
    if len(xs) == 0:
        raise ValueError("median() requires at least one value")
    s = sorted(xs)
    n = len(s)
    mid = n // 2
    if n % 2 == 1:
        return s[mid]
    else:
        return (s[mid - 1] + s[mid]) / 2


def mode(xs: list[float]) -> list[float]:
    if len(xs) == 0:
        raise ValueError("mode() requires at least one value")
    counts = {}
    for num in xs:
        if num not in counts:
            counts[num] = 1
        else:
            counts[num] += 1

    highest = max(counts.values())
    return [num for num, c in counts.items() if c == highest]
// JavaScript (the port this page runs)
function mean(xs) {
  if (xs.length === 0) throw new Error("mean() requires at least one value");
  return xs.reduce((a, b) => a + b, 0) / xs.length;
}

function median(xs) {
  if (xs.length === 0) throw new Error("median() requires at least one value");
  // sort a copy with a numeric compare:
  // plain .sort() compares as text, so [10, 9, 100] -> [10, 100, 9]
  const s = [...xs].sort((a, b) => a - b);
  const n = s.length;
  const mid = Math.floor(n / 2);
  if (n % 2 === 1) return s[mid];
  return (s[mid - 1] + s[mid]) / 2;
}

function mode(xs) {
  if (xs.length === 0) throw new Error("mode() requires at least one value");
  const counts = new Map();
  for (const num of xs) counts.set(num, (counts.get(num) || 0) + 1);
  const highest = Math.max(...counts.values());
  return [...counts].filter(([, c]) => c === highest).map(([num]) => num);
}

Two details worth noticing. median sorts a copy, so the caller's list is never changed. And mode returns every value that ties for the top count, so if every value appears exactly once, it returns all of them: a sign that the mode tells you nothing about that dataset.
